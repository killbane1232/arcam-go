# Arcam Research

Работай с исследовательским MCP Arcam. Результат — проверяемый эксперимент с конкретной версией стратегии, входными данными, расходами и run ID, либо точная диагностика проблемы.

## Подключение и выбор инструментов

Обнаружь инструменты подключённого сервера `arcam` и прочитай их актуальные схемы. Ниже используются имена сервера без клиентского префикса. В Hermes это обычно `mcp_arcam_get_catalog`; в Codex префикс зависит от среды — используй фактически обнаруженное имя.

Вызови `get_catalog` перед созданием новой стратегии: он содержит актуальные индикаторы, операторы, интервалы и рабочие примеры. Загружай `list_strategies`, `list_datasets`, `list_backtests` по потребности; не выгружай всю историю для одного известного ID.

Если инструменты отсутствуют или соединение не проходит, открой [подключение и диагностику](references/connection.md). Исправный `/healthz` сам по себе не доказывает работу MCP. Встроенный `scripts/mcp_smoke.py` проверяет handshake и чтение без записи. Наличие скилла само по себе не подключает сервер.

## Выполнение задачи

1. **Уточни эксперимент из контекста.** Зафиксируй гипотезу, источник, пары, таймфрейм, точные даты, капитал, комиссию и проскальзывание. При отсутствии несущественных параметров предложи и явно обозначь допущения. Если выбор меняет смысл исследования, уточни его до запуска. Для проверки интеграции подходит DEMO; для оценки рыночной гипотезы требуются реальные данные. Не подменяй запрошенный источник.
2. **Подготовь стратегию.** При работе с существующей версией используй её точный ID и номер. Для новой версии начни с примера каталога или нужной существующей стратегии; запиши проверяемую гипотезу в `description`. Изучи [DSL и контракт инструментов](references/contracts.md) при изменении правил. В `strategy_json` передавай сериализованную JSON-строку всего объекта Strategy, а не вложенный объект или обёртку Version.
3. **Проверь и сохрани.** Вызови `validate_strategy`, используй возвращённый `warmup`. Если пользователь просил только проверку, закончи без сохранения. Для запуска новой стратегии вызови `save_strategy` и возьми `id`, `version`, `hash` из ответа. Каждый вызов создаёт новую неизменяемую версию, в том числе при повторении того же содержимого.
4. **Проверь данные и запусти.** Для DEMO/CSV проверь локальное покрытие нужного `source + symbol + interval`, включая прогрев до `from`. Для Binance недостающая история загружается автоматически. Выполни `run_backtest` с явной версией, датами и расходами. Без задачи на LLM используй стратегию без `llm`, `allow_llm=false`, `max_llm_calls=0`.
5. **Дождись результата.** Сохрани возвращённый run ID и опрашивай `get_backtest`. `queued`, `preparing`, `running` — промежуточные статусы, а не успех. Для короткого расчёта достаточно пауз 1–2 с; при ожидании сети/LLM увеличивай их до 5–10 с. Следи за `progress`, `backtest_progress`, `llm_stats`. При `failed`, `cancelled`, `interrupted` объясни причину и отдели частичные данные от итоговых. Запрос остановки выполняй через `cancel_backtest`, затем проверь статус.
6. **Объясни результат.** Для причин входа/выхода получи небольшой диапазон `get_decisions` выбранной пары. Разделяй время решения и время исполнения; разбирай `rules`, `ready`, `skipped`, позицию, LLM-статус и fills. При сравнении используй `compare_backtests` только для завершённых запусков и проверь `same_inputs`. Правила корректного сравнения и LLM находятся в [методике исследования](references/research.md).

## Важные границы

- Все даты запросов — RFC3339 UTC, диапазон `[from,to)`, границы кратны таймфрейму. Преобразуй локальное время пользователя в UTC явно. `to` не может быть в будущем.
- DEMO — синтетические свечи. Результат на них подтверждает работу механики, а не доходность на рынке.
- Сигнал после закрытия свечи исполняется на открытии следующей. Одна позиция на пару; немедленного разворота нет.
- `save_strategy`, `run_backtest`, `import_history` меняют хранилище. После таймаута не повторяй их вслепую: проверь версии, запуски или наборы данных, чтобы не дублировать работу. Повторный импорт может обновить существующие свечи.
- MCP не содержит инструментов paper/live-сессий, выставления ордеров, настройки LLM или CSV-импорта. Не обходи это ограничение через REST ради исполнения исследовательского запроса. Если нужна отдельная операция вне MCP, обозначь её явно и действуй только в рамках соответствующей задачи пользователя.
- LLM с внешним провайдером требует согласованного использования и конечного бюджета вызовов. Сохраняй уже данное разрешение; не запрашивай его заново для каждого вызова в пределах задачи. Не включай LLM ради обычного smoke-test.

## Что вернуть пользователю

Для бэктеста укажи `run_id`, статус, `strategy_id@version`, источник, пары, период/таймфрейм, капитал и расходы. Приведи доходность, максимальную просадку, число закрытых сделок, win rate и комиссии; отсутствие сделок не интерпретируй как доказательство качества. Для сравнения добавь `same_inputs`, различия условий и отдельный результат на отложенном периоде, если он проверялся. Отметь синтетические или частичные данные, а также ограничения, существенные для вывода. Не обещай будущую доходность по результатам бэктеста.
